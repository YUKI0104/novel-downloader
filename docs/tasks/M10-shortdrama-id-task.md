# M10：短剧命中改按「小说ID」+ 详情页展示后台全量数据

> 用户拍板：Q1 甲（全字段展示）／Q2 甲（把现有小条扩成两行数据块 + 标签行）／Q3 乙（角标带信息）／Q4 乙（加「在后台打开」）。
> 侦查结论（已实测，见提交 `8984c65` 的 `sd-probe` 钩子）：`book_id=<ID>`（别名 `ip_book_id`）可命中；`novel_id`/`keyword`/`book_ids` 等**被静默忽略并返回默认 20 条**，禁止使用。

## 1 数据层（`Sources/Core/Shortdrama/ShortdramaClient.swift`）

### 1.1 先把 ID 精度修掉（前置，必须）
- 现状：`strOf`/`intOf` 走 `.number(let n)`（Double）→ 19 位 ID 尾数被抹：真值 `7613834044236631102`，读到 `7613834044236631040`。
- 要求：JSON 整数按**原始字面量**保真（推荐在 `JSONValue` 的 number 分支保留原始文本，或新增 `.integerText(String)`；解析时若字面量是纯整数且位数 > 15 就走文本）。`ip_book_id` / `ip_id` 全链路按**字符串**取值、比较、拼 query。
- 自检必须证明：读出的 `ip_book_id` 与真值 `7613834044236631102` **逐字符相同**。

### 1.2 按 ID 查
- 新增 `searchByBookID(_ id: String) async throws -> [ShortdramaIP]`：URL 与现有 `shortdramaSearchWithSession` 同，仅把 `book_name=` 换成 `book_id=<ID>`（其余参数保持 `page_no=1&page_count=20&image_fmt=180x240&op_channel=1&ip_adaptation_type=2&aid=791322`）。
- **命中判定**：返回 `ip_list` 里必须存在一条 `ipBookID == 传入 ID`（字符串精确相等）才算命中；否则一律视为未命中（防「参数被忽略返回默认 20 条」导致误判）。

### 1.3 批量查询改签名
`searchTitles([String])` → `searchBooks([(id: String?, title: String)])`：
- 有番茄 ID：**先按 ID 查**；未命中再**回退按书名**（兼容「后台书名 == 番茄书名」的情况）。
- 无番茄 ID（七猫书）：只按书名（与现状一致）。
- 保持 3 并发 worker；任何失败只记进 `Batch`，绝不抛错、不挡主流程、关开关时不读登录态。

### 1.4 新增字段（全部字符串化，增量加在现有结构体上，旧字段不删）
| 页面文案 | JSON 键 | 口径 |
|---|---|---|
| 体裁 | `ip_source` | 1网文/2故事/3出版/4电影/5电视剧/6游戏/7动漫/8漫画/9其他，其余→「未知」 |
| 作者 | `author_name` | 现字段 `author` |
| 评分 | `book_score` | 现字段 `score` |
| 完结状态 | `creation_status` | 0已完结／1连载中 |
| 字数 | `word_num` | 展示按现有 `FMFormat` 万/亿 口径 |
| 在读 | `read_listen_dcnt_14d` | 展示「25.9 万人在读」 |
| 读者占比 | `middle_/old_/young_read_duration_rate` | 0–1 浮点 → 百分比**一位小数**（66.3%） |
| 被挑选次数 | `ip_selected_count` | 现字段 `selectedCnt` |
| 已上架短剧数 | `ip_shelved_count` | 新增 |
| 等级标签 | `ip_tier_level` | 0未知/1典藏IP/**2精品IP**/3潜力IP |
| 性别标签 | `gender` | 0女频/1男频/其余→未知（注意与 `ip_genre` 区分） |

| 改编中 | `same_ip_adapting_count` | 现字段 `adaptingCnt` |

## 2 详情页（Q2 甲）
把现有「上架 / 申请 / 改编中」小条扩成**数据块**（同区位置，沿用现有等宽小字 + 图标样式）：
- 第 1 行：`体裁｜作者｜评分｜已完结/连载中｜字数｜在读`
- 第 2 行：`读者占比：中年 66.3% 老年 19.3% 青年 14.3%｜被挑选 1 次｜已上架 0 部`
- 第 3 行：标签胶囊（`精品IP`（强调色） + 女频/男频 + `category_list` 各项）
- 第 4 行：`榜单：阅读榜`（含历史峰值榜则追加；都没有则整行不显示）
- **高亮规则**：`被挑选次数`/`已上架短剧数`/`改编中` > 0 时用警示红（沿用旧「申请>0 高亮」的视觉）。
- **不许截断文字**（用户红线）：一行放不下就换行，不许省略号截断；确认详情弹窗仍 950×600、内容不溢出、不遮挡下载按钮。

## 3 卡片角标（用户 2026-10-11 改口径）
**不再出现「短剧」字样**；角标文案固定为 `上架N部·申请N次`：
- `N` 分别取后台的 `ip_shelved_count`（已上架短剧数）与 `ip_selected_count`（申请/被挑选次数）。
- 两段都要显示（即使为 0，如 `上架0部·申请0部`）；**>0 的片段用警示红加重，=0 的片段灰字**。
- 整体仍是「命中」标识，位置仍在卡片封面右上角、不遮挡封面主体与书名；放不下可两行，**不许截断**。

## 3.1 排序口径（用户 Q1 乙 / Q2 乙）
- **榜单页**：**完全保持原排名顺序**（TOP 10 就是 TOP 10），命中只体现在红框 + 角标 + 状态行计数上；**禁止**再 `filter(命中)+filter(未命中)` 重排。
- **搜索页**：只把**命中的书稳定地提到最前**（组内保持番茄原相对顺序），其余也保持番茄原相对顺序；**删除**现有的多级排序（上架月份→在读→字数→改编中→被挑选）。
- 状态行文案不变（`TOP N · 频道 · 平台 · M 本在短剧后台` / `共 N 条结果 · M 本在短剧后台`）。


## 4 「在后台打开」按钮（Q4 乙）
- 详情页数据块右侧（或块内右上）加按钮，文字必须自解释：**「在后台打开」**。
- 点击用 `NSWorkspace` 打开默认浏览器到短剧后台并尽量定位到该 IP（优先 `https://www.shortdramas.com/page/ip-application` 带 `book_id=<番茄ID>`；若实测该页不认这个参数，就打开 IP 申请页并在报告里说明）。
- 无命中（未登录/不在后台）时不显示这个按钮。

## 5 自检与取证（必须真跑）
- `sd-id`：① ID 精度（读出 `ip_book_id` == `7613834044236631102`，逐字符）；② 按 ID 命中《花妖军嫂种出万亩绿洲，系统崩了》(ID 7613834044236631102) → `ip_name=《家妻非人，但实在美味》`；③ 同一本在**搜索**与**详情**两条路径都能命中（用户报的就是这本）。

- `sd-hit`：搜索/榜单卡片角标文案实测（含「短剧 · 上架 N 部」/「短剧 · 已选 N」/「短剧」三态）。
