# M3-g 任务书（小）— 榜单/搜索请求失败时的可感知反馈

不是新功能，是**用户实际会撞到的体验坑**。

## 现象（实测证据）
`~/Library/Application Support/FanQieMao/logs/app.log` 里 14:12 那次普通启动：
- 第一次请求榜单撞到站点侧 `HTTP 515`（CDN/风控抖动，非我们代码问题）；
- 之后自己重试成功，但**前后花了 41 秒**，这期间界面只有空网格/旧内容，用户不知道在干嘛。

## 要做的
1. 榜单/搜索请求失败后**自动重试最多 3 次**（间隔递增，例如 1s / 2s / 4s），别用现在这种很长的等待。
2. 重试期间状态行（就是「TOP 10 · 综合热榜 · 番茄」那一行）要给出**可感知的反馈**，例如「网络不稳，正在重试 2/3…」；成功后恢复正常文案。
3. 3 次都失败 → 状态行显示简短失败原因 + 一个「重试」按钮（**复用现有状态行/按钮样式**，不许新造型、不许加弹窗）。
4. 文案与风格与现有状态行一致（灰字、短、不堆句子）。

## 红线
- 不动榜单接口/频道/排序逻辑；不动窗口 1000×800、卡片 176.8×293.0、弹窗 950×600、左右留白 30/30、列数 5。
- 短剧后台失败仍然不许影响主流程（已有行为，别退化）。

## 交回
1. 造一次失败（断网或把域名指到黑洞/打桩返回 515）→ 截图：重试中的状态行 + 失败后的「重试」按钮；贴日志证明重试间隔与最终成功/失败。
2. `chain` 回归绿；布局数值未变。
3. 纪律：先 `ps aux | grep FanQieMao`；只跑必要轮次；跑完 `bash Tools/跑.sh` 留在普通启动（带签名）；settings 原值 `ignored=true`/`prompted=true`、平台=番茄。
