# M1.4 任务书 — 修右边缘：内容不许被滚动条压住/切断

## 0. 现象（我自己看截图量出来的，不是自述）
- 列表模式 `/Users/yuki/.hermes/cache/scratch/shots/m13-02-list.png`：每行右侧的「ID 数字」**被切断**——放大右上角可见 `ID 7673521851523419▌`、`ID 7652408518770691▌`，后面几位被压在滚动条下面/被裁掉；ID 是 19 位，用户一眼就能看出少了几位。
- 封面网格 `/Users/yuki/.hermes/cache/scratch/shots/m13-01-album.png`：**最右列卡片被滚动条压住**（滚动条直接浮在封面右缘上，卡片像被切了一条）。
- 你自报的"右 Δ=0.0"是布局 frame 的数字，但视觉上内容的右 17pt 落在滚动条底下，所以对齐是假的。

## 1. 根因（你自己在报告里写了）
`contentMargins(.trailing, -17, for: .scrollContent)` 把内容右移 17pt 去凑顶栏右边缘；但 macOS 传统（占位式）滚动条要占 17pt 且绘制在内容之上 → 内容右缘被压。

## 2. 要改成什么
目标：**内容右边缘与顶栏右边缘对齐（Δ≤1pt），同时内容不被滚动条压住、不被切断**。
- 做法：让滚动指示器走**覆盖式（overlay）**，不占布局宽度 —— App 启动时设 `NSScroller.preferredScrollerStyle = .overlay`（这是全局用户偏好，旧版是 WKWebView 自带的浮层滚动条，观感一致），必要时配合 `autohidesScrollers = true`。
- 不要再靠负 `contentMargins` 顶着滚动条凑数；恢复正常的 0 边距，让内容可用宽度 = 顶栏宽度。
- 列表模式行内右侧要有正常的 padding（≥18pt），ID 19 位必须完整可读；封面网格最右列卡片必须完整。

## 3. 禁止
- 禁止改动：网格/列表的结构与数值、弹窗、遮罩与关闭路径、窗口玻璃、顶栏元素、内核与下载逻辑、文案与配色。

## 4. 交付与验收（交给我）
1. 列表模式右上角**放大截图**：能读出完整的 19 位 ID（不许有被切的位）。
2. 封面网格右上角**放大截图**：最右列卡片完整、滚动条不压内容。
3. 两种模式下左 Δ、右 Δ 的数字（≤1pt）。
4. 说明滚动条改成覆盖式后，滚动手感/外观是否与旧版一致（贴一句自己的观察）。
